[2026-09-17 7:08 a.m.] mole99
Hi @Simo6572,

Was your previous chip created using the same GF180MCU process and a proprietary PDK, or did you use a different process?

Note that the foundry-provided standard cell library in the open-source PDK uses the high-voltage transistors, which are slow. Tholin made a community-created standard cell library using the low-voltage transistors, which is much faster running at 3.3V. However, it hasn't been tested yet (the wafers are coming out of the fab this week).

[2026-09-17 10:40 a.m.] namibj
You'll have to use the Avalon Semiconductors 3v3 SCL to have a good chance; there's an SRAM compiler giving much better density than the foundry open PDK macros offer by @Chips4Makers aka Staf Verhaegen .

Note that the Avalon 3v3 SCL isn't currently too production-ready but that's mostly because there may be bugs left that haven't yet been caught through extracted SPICE behavioral sanity checking.
For purposes of determining if you can do an RTL on a wafer.space slot at least near a target speed, it should suffice.


[2026-09-17 10:53 a.m.] mole99
Note that you can also use Tim Edwards' SRAM macros, which are shrinked versions of the foundry ones.


[2026-09-17 10:53 a.m.] mole99
