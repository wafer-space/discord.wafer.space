I want to propose to port/convert the gf180mcuD 3.3V and 5/6V FETs to PSP 103 (though that seems to be kinda EOL recently, and evolved/major-version-switched to PSP 104 that's just a bit incompatible but would be more capable and _I think_ could be used to code the (iirc heavily in geometry restricted by the DRCs we're subjected to, thus making it much easier to bend the PSP model card to represent that LDMOS structure, even if it's not made to be used for modeling flexibile-geometry LDMOS structures) 10V LDNMOS and 10V LDPMOS we get).

It's numerically far nicer than BSIM4, which should help with nonlinear convergence especially if arc length continuation is used or for things like harmonic balance:

...and adjoint-sensitivity-based "efficient" monte-carlo/bayesian-style polynomial chaos expansion:
  - basically if you compute through backpropagation the sensitivity to meaningful output measurement numbers as a function of all the monte carlo affected input random variables,
  - you can use that with knowledge of the input variation distributions (which you sample from for monte carlo anyways),
  - to pick far more efficient samples than random monte carlo
  - for the goal of providing a good stochastic estimate of some measure of the distribution of those output measurement numbers: example is expected chip yield for a target +-5% cutoff.

Also the numerical cleanliness should aid in numerically model-fitting based on statistically significant DUT samples, through clean and thus optimizer-friendly backpropagation gradients.

and given that IHP SG13 is an RF-focused process family with it mostly existing/being created for supporting their Si:Ge HBT application research efforts, I'd tend to trust their usefulness for analog and RF circuits more than the legacy BSIM stuff that's source-referenced (meaning the math gets unfortunately fairly gnarly inside if you accidentally extract a source as a drain because their model doesn't feel like computing in a way that numerically doesn't care if source is source and drain is drain (or they are swapped)) and also this should allow more effective coding of bent gates as a result from the math being cleaner.
